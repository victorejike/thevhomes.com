## 2. Duplicate Detection

### URL-Level Duplicate Check
**Location:** `backend/internal/handlers/property_handler.go` (modified)
- `firstDuplicateImage()` helper function
- Rejects listings where the same URL appears multiple times
- Normalized comparison (case-insensitive, whitespace-trimmed)

### Perceptual Image Hashing
**Files:**
- `backend/internal/utils/imagehash.go` (new, 123 lines)
- `backend/internal/utils/imagehash_test.go` (new, 135 lines, 7 test cases passing)

**Algorithm:** Difference Hash (dHash)
- Resizes image to 9×8 grayscale grid
- Compares adjacent pixels in each row
- Produces 64-bit hash from comparison results
- Hamming distance ≤5 = duplicate (tolerates re-compression, resizing)

**Test Coverage:**
- ✅ Identical images across JPEG/PNG formats
- ✅ Same photo at different resolutions (800x600 vs 200x150)
- ✅ Different JPEG quality levels (95% vs 40%)
- ✅ Distinguishes genuinely different photos
- ✅ Rejects non-image input gracefully

**Integration:**
- Hashes computed during property creation (`property_handler.go`)
- Stored in `property_images.perceptual_hash` column
- Best-effort: fetch/decode failure never blocks listing creation

### Completeness Scoring (0-100)

**Algorithm:** Deterministic weighted rubric

**Weights (sum to 100):**
- Title: 6
- Description: 16
- Price: 6
- Location: 14 (country, state, city, area, address)
- Coordinates: 6
- Details: 16 (type-specific fields only)
- Amenities: 10
- Images: 18 (count + cover photo)
- Video: 8

**Per-Type Detail Scoring:**
- Residential (apartment/villa/duplex/shortlet): bedrooms, bathrooms, toilets, parking, building size, year built
- Land: land size only
- Commercial/Office/Warehouse: building size, parking, toilets, year built
- Hotel: rooms (= bedrooms), bathrooms, building size
- Event Centre: building size, parking, toilets, year built

**Explainability:**
- `Breakdown()` returns per-field `{ field, earned, max, hint }`
- Hints tell agents exactly what to fix: "Add latitude and longitude so the property appears on the map."
- Never a black-box score — agents see which fields are incomplete

**Test Coverage:**
- ✅ Complete listing scores ≥95%
- ✅ Empty listing scores ≤10%
- ✅ Monotonic (removing video lowers score, never raises it)
- ✅ Land not penalized for residential fields
- ✅ Every incomplete field has an actionable hint

### Moderation Scoring (0-100)

**Algorithm:** Rule-based pattern matching with weighted signals

**Policy Violations Detected:**

| Signal | Weight | Pattern |
|--------|--------|---------|
| Contact phone | 45 | Nigerian phone number in text |
| Contact email | 40 | Email address in listing copy |
| External link | 40 | URL to another website |
| Off-platform contact | 45 | "WhatsApp", "Telegram", "DM me" |
| Irregular payment | 45 | "Bitcoin", "USDT", "Western Union" |
| Discriminatory terms | 75 | Ethnic/religious tenant restrictions |
| Profanity | 30 | Abusive language |
| Pressure tactics | 15 | "Act now", "today only", "hurry" |
| Unrealistic claims | 20 | "100% guaranteed", "no inspection needed" |
| All-caps title | 10 | Shouting (≥12 letters, all uppercase) |

**Threshold:** ≥40 → routes to moderation queue

**Weak Signal Stacking:**
- Single weak signal (e.g. "act now") = 15 points → clear
- Multiple weak signals (all-caps + urgency + guarantees) = 45 points → flagged

**Never Auto-Deletes:**
Per Phase 4 spec: "Do not automatically delete content. Instead: Assign a moderation score."
- High score → `moderation_status = "pending_review"`
- Admin sees listing with rule breakdown
- Admin decides: "dismiss" (clear) or "uphold" (request changes)
- Automated scoring never hides or removes a listing

**Privacy:**
- Contact details in moderation signals are redacted: `080312•••67`
- Full number never appears in moderation log

**Test Coverage:**
- ✅ Clean listing passes with status "clear"
- ✅ Phone/email/link/crypto/discrimination all flag independently
- ✅ Weak signals stack correctly
- ✅ Scoring never mutates listing visibility
- ✅ Contact details redacted in signals

## 9. AI Engine: Self-Contained Design

### Core Functionality Without External Dependencies

Per Phase 4 spec: *"This AI is a core part of the platform and must not depend on proprietary third-party AI APIs for its core functionality."*

**Rule-Based Modules (Always Available):**
1. **Completeness Scorer** — deterministic weighted rubric
2. **Moderation Scorer** — regex pattern matching

These run with **zero external API calls** and require **no configuration**. The engine is instantiated with `ai.NewEngine()` and works immediately.

### Optional LLM Enhancement

**Location:** `backend/internal/handlers/ai_handler.go`

The existing AI assistant endpoint (`POST /api/v1/ai/ask`) has dual mode:
- **Fallback:** Rule-based intent parser (regexes for cities, property types, price ranges)
- **Enhanced:** OpenAI function-calling when `OPENAI_API_KEY` is set

**Key Point:** LLM is for *conversational search*, not core listing quality. Completeness and moderation scores never depend on OpenAI availability.
